## Decision record format

For each closed item record: human name and role; decision date; approved choice and scope; alternatives/rationale; affected task/schema/template/configuration/policy versions; jurisdiction/effective/review dates where relevant; primary source/evidence links; risks; implementation owner; review trigger; and the approving record/ADR. Secrets belong in the approved environment secret store, never in this register or a commit.

## Blocker interpretation

- Open owner/project/settings choices prevent claiming those external acceptance criteria as satisfied; they do not block repository inspection, typed foundation code, documentation, local tests or synthetic visual review.
- Missing provider access blocks authentic provider sandbox/production integration evidence. A test adapter cannot establish that real payments, email, backups or production isolation work.
- Unknown legal rules or unapproved high-risk language block the affected claim/calculation/workflow from production via feature flag. A generic disclaimer does not substitute for required qualified review.
- The literal task graph is cyclic. Record the proposed staged registry/evidence resolution before representing out-of-order completion as specification compliant.
- Go-live is a separate human gate even if every engineering check passes. No entry in this file records approval by implication, elapsed time or AI assertion.
