# ADR NNNN: Decision title

Status: proposed / accepted / superseded. Date: YYYY-MM-DD. Proposed accountable role: pending. Named decision-maker/reviewer: pending. Related task(s), source requirement and superseded ADR: pending.

## Context and requirement

State the concrete problem, PDF requirement and current implementation. Identify whether this is an engineering choice, dependency interpretation or requested scope deviation. Do not assume user approval.

## Options and decision

Describe viable alternatives, selected option, rationale and operational cost. Record what remains unimplemented. For a required human decision, attach the named approval and date; leave status proposed until received.

## Consequences and controls

Document security/privacy/accessibility/legal effects, tenant boundaries, compatibility, dependency ordering, migrations, data retention, vendor assumptions, rollout/rollback and feature flags. Identify affected schema/template/renderer/copy versions and authoritative source registry entries where applicable.

## Evidence and review trigger

Link tests/results, actual UI/rendered inspection, task report and focused commit. Specify owner, unresolved risks and precise review triggers or expiry. State whether a requirement deviation is approved, by whom and with what scope; do not infer approval from implementation.
